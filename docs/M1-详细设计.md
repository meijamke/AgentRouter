# M1 详细设计 v4 · agent 多步路由（三模式 + 离线答案表 + 查表训练）

> 对应《四设备模型路由·架构方案 v22》的 M1 里程碑。
> **范围**：agent 多步路由，单层 MDP，3 档设备（weak/medium/strong），**三种路由模式（single/multi/agentic）**。
> **v4 核心（今天正本清源后的最终形态）**：
> 1. **骨架 = Hera（step-level 多步）**，RLCascadeRouter 的 VAS/CE 为实现；
> 2. **M1 就学三路由模式**（RouteWeaver）：动作空间 = `{停} ∪ {single, multi, agentic} × 设备`，模式不写死；
> 3. **删 P(fail)**（quality-estimator-free），升级信号推迟 M2；
> 4. **训练 = 离线答案表 + 查表**；IL 用 Handoff supervision target；RL 用 RIVET response-informed 值估计；
> 5. **β 只作评估天花板（1−β）**，不学、不做 ROI gate、不做模式剪枝。

---

## 0. 一句话

一个 query 拆多步；每步策略在 `{停} ∪ {single/multi/agentic} × 设备` 里选一个（模式 × 设备）；奖励 = 最终成功 − 累计成本；**训练前建"设备×任务答案表"，训练时查表**；核心 = "用最便宜的够用设备、学选对模式、学何时升级"。

---

## 1. 自建 benchmark（路由模式 × 难度 二维分层）

**两个轴**：①**模式轴**（让策略学三模式，RouteWeaver）；②**难度轴**（让 weak/medium/strong 真实分化）。

| 模式 | 题型 | GT 可验证 |
|---|---|---|
| **single**（一步答完） | 单步 QA/算术（"37+25=?"） | ✅ 数值 |
| **multi**（多步前进） | 多步依赖链（"先算 X，再据 X 算 Y"） | ✅ 数值 |
| **agentic**（工具调用） | 调工具（"用计算器算 9876×5432"）→ 工具=预定义可验证函数 | ✅ 执行比对 |

每个模式内分 **easy/medium/hard**：easy 三档都过、medium weak 大概率错、hard 仅 strong 稳过。

**关键（调硬 + 分化验证）**：medium/hard 必须**真让 weak 做错**（此前"判断质数"太软，weak 全会；AppWorld 单次真执行又太硬三档全 fail）。建表前先"弱强分化验证"（3 模式 × 3 难度 × 3 设备试跑），不分化就继续调硬。

---

## 2. 离线答案表（训练前一次性建）

```
对每个 task × 每个设备：调真实 API → 拿答案 + 成本 → 判对错（对照 GT）
→ answer_table[task][device] = (correct: bool, cost: float)
```

- 规模：N 任务 × 3 设备 = 3N 次 API 调用，一次性付清；
- 之后 IL/RL **全查表**：几十万局不碰真实 API（解决真执行慢 + API 超时）；
- 建表即"最便宜够用设备"的 GT 来源：`label(task) = 最便宜且 correct=True 的设备`。

---

## 3. 策略网络（VAS + CE + 模式门，quality-estimator-free）

```
CE： self-attention 处理 {Stop} ∪ (模式×设备) 实例 → 打分（能力互补）
     e_i = [h_s; cap_embed_i; 状态_i; f(q,device_i)]
VAS： 模式门 产 {停, single, multi, agentic} logits + Critic
最终： softmax(mask([logit_stop] ∪ [logit_mode + score_i] ∪ [logit_agentic + score_tool_j + score_i]))
```

- **无 P(fail)**（删掉，回 quality-estimator-free）；升级信号推迟 M2 且过"五种自欺"清单；
- λ 条件化进状态（换 λ 免重训，RouteFM）。

---

## 4. 训练管线

### 4.1 IL 冷启动（只当"不崩"初始化 + Handoff supervision target）

```
① 标签 = 最便宜够用设备（答案表 GT，非静态代理）
② 吸收 Handoff（2610.15993）：标签用"剩余工作所需能力档 + 前方困难步"（monotone fit），
   不用"噪声逐步对错"
③ 交叉熵训 VAS/CE；目的只是"先选最便宜的够用设备、别崩"
```

### 4.2 cost-aware RL（核心 · 查表采样 + RIVET）

```
① 以 IL 权重初始化
② 查表采样：每步策略采样 (模式,设备) → 查表拿 correct/cost + 该步 response → 更新状态
③ 奖励 = 最终成功 − λ·累计成本（+ shaping r_t=ΔU，γ=1）
④ 吸收 RIVET（2610.23239）：training-only 的 response-informed value estimator
   （看得到 response），部署仍 pre-call
⑤ REINFORCE/PPO + exploration，学"single 一步够 / multi 多步 / agentic 调工具 + 何时升级"
```

**查表使 RL 能大规模探索**：几十万局采样，把"weak 在哪些任务错、错后升级值不值、哪种模式最省"全学出来。

---

## 5. 验收标准（M1 gate · 守弱）

| 项 | 标准 |
|---|---|
| **成本节省**（主） | 同样成功率下，成本显著 < 纯 strong 基线（路由天花板=strong，收益在省钱） |
| 成功率 | ≥ 纯 weak 基线；接近 oracle（最便宜够用） |
| **β 天花板** | 1−β 作"多模型组合收益上限"（只评估，不学、不做 ROI gate） |
| 统计严谨 | 多种子（不只 seed 42）+ 标准差/置信区间 |
| 消融 | 比 Pareto 前沿（多 λ），不拆两列只盯成功率 |
| **评测基准** | **TwinRouterBench 开源仓**（per-step 标签 + live SWE-bench + leaderboard）为主；RouterWorld 作补充 |
| 跨域 | AppWorld/ALFWorld/WebShop 测迁移（RouteFM 少样本路线，零样本不预设） |

---

## 6. 开发顺序

```
0 二维 benchmark（模式×难度）→ 1 弱强分化验证（3×3×3 试跑）→ 2 建答案表（3N 次）
→ 3 IL（Handoff target 初始化）→ 4 RL（RIVET + exploration）→ 5 TwinRouterBench 评估（β 天花板）
```

> 依据：为什么单层 MDP/Hera 主骨架 → 架构 v22 §2；为什么三模式 → RouteWeaver；为什么离线答案表+查表 → RLCascadeRouter §4.3；为什么删 P(fail) → 升级信号簇（TRIAGE/CreateScore/Who Pays）；为什么 β 只作天花板 → β 是反事实宏观量。
