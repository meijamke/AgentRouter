# M1 详细设计 · agent 多步路由（任意在线设备）

> 对应《四设备模型路由·架构设计与整体方案 v17》的 M1 里程碑。
> **范围**：agent 多步路由，**单层 MDP**，任意在线设备（能力由 `cap_embed` 表示）；入口设备迁移成本=0，其它设备迁移成本>0。
> **M1 边界**：只用 L1/L2/L3/L4 四层（L4=训练；记录器、灰度下发 → M2）；必读 2 篇 = Hera（训练）+ RLCascadeRouter（VAS/CE）。
> **设备抽象**：设备 = 实例（device_id），用 `cap_embed`（能力嵌入向量）+ 状态描述；`can_execute=False` 的设备不进动作空间。
> **不做**：四设备全池（M3）、在线更新（M2）、选角色/图记忆（GraphPlanner，M4）。
> **训练**：Hera 两阶段 = IL 冷启动 + cost-aware RL；**策略**：RLCascadeRouter 的 VAS/CE。

---

## 0. 一句话

一个 query 拆多步；每步由 VAS/CE 策略在 {Stop} ∪ 在线设备实例里选一个；"重试" = 下一步换更高能力设备；奖励 = 任务最终成功 − 累计调用成本。

---

## 1. 数据模型（`schema.py`）

```python
@dataclass
class DeviceState:
    device_id: str
    cap_embed: list          # 能力嵌入向量（如 [文本/代码/数学/多模态] 或可学习 embedding）
    battery_pct: float
    temp_c: float
    mem_free_gb: float
    network_bw_mbps: float
    can_execute: bool         # 能否执行推理（纯 I/O 设备如手表 → False）
    online: bool
    last_heartbeat: float

@dataclass
class StepState:
    trajectory_summary: list   # 已完成步骤摘要（输出 + 结果）
    progress: list             # 任务进度（ProgRouter 式 multi-view：粗 regime + 细完成度/趋势）
    last_output: str           # 上一步输出
    p_fail: float              # 上一步失败概率（Brier 校准）
    cost_accum: float          # 累计成本（延迟+能耗+KV迁移）
    device_states: list        # List[DeviceState]
    step_idx: int

@dataclass
class StepAction:
    action: str                # "stop" 或 device_id（单一字段，无冗余）
    p_fail: float

@dataclass
class StepObservation:
    latency_ms: float
    energy_j: float
    kv_bytes: int              # 跨设备 KV 迁移量
    kv_ms: float
    quality: float             # 本步质量（GT/过程验证器）
    success: bool

@dataclass
class Trajectory:              # 训练记录单元
    states: list               # List[StepState]
    actions: list              # List[StepAction]
    final_success: bool
    total_cost: float
```

## 2. 策略网络（VAS + CE，具体结构）

```
① Encoder:
   trajectory_summary ⊕ progress ⊕ last_output_embed ⊕ cost_accum ⊕ device_states
   → h_s ∈ R^d

② CE（Complementarity Encoder）:
   # 动作空间动态：对每个"在线可执行设备实例"生成一个 token（数量/类型可变）
   action token: e_i = [h_s; cap_embed_i; 状态_i; f(q, device_i)]
                 f(q, device_i) = MLP(query_embed ⊕ cap_embed_i)   # query-设备匹配，多维能力
                 e_stop = [h_s; embed(stop)]
   self-attention over { e_stop, e_i (∀ 在线设备) }
   → { ẽ_stop, ẽ_i }
   score_i = MLP(ẽ_i)                      # 每设备"下一步价值"打分

③ VAS（Value-Aware Stopper）:
   c = MeanPool({ẽ_stop, ẽ_i (∀ 在线设备)})
   [logit_stop, logit_cont] = StopGate([h_s; c; p_fail])   # p_fail 是 VAS 输入特征，非独立决策
   V(s) = Critic([h_s; c])                 # 价值函数（RL 用）

④ 输出:
   logits = [logit_stop] ∪ [logit_cont + score_i]
   π(a|s) = softmax(mask(logits))          # mask 掉 offline 设备
```

**P(fail)**：`p_fail = calibrate(g(集成分歧 ⊕ token熵 ⊕ logP ⊕ 设备状态))`，Brier 校准到真实失败概率，作状态喂 VAS。

## 3. 推理 loop（伪代码）

```
def route_agent(query):
    s = init_state(query)                 # StepState
    result = None
    for step in range(MAX_STEPS):         # 软步数上限（防无限重试，非硬 T_max）
        a = policy(s)                     # VAS+CE → {stop} ∪ 在线设备实例
        if a.action == "stop":
            return result                 # 任务完成
        obs = execute(a)                  # 本机（迁移0）/ 其它设备（KV迁移+传输）
        result = obs.output
        s = update_state(s, a, obs, p_fail(obs))
    return result                         # 达软上限，返回当前结果
```

- `execute(本机)`：入口设备本地推理，迁移成本 = 0；
- `execute(其它设备)`：跨设备 **卸载 + KV 迁移 + 传输**（记录 kv_bytes/kv_ms，计入成本）。
- 执行前 final liveness 检查（设备掉线 → mask 重选）。
- `MAX_STEPS`：软步数上限（如 20），防策略卡在无限重试；非硬约束（正常任务几到十几步内完成）。

## 4. 训练管线

### 4.1 IL 冷启动（Hera 式）

```
① 最高能力档设备在 **ALFWorld + WebShop + AppWorld**（Hera 同款三 benchmark）上跑 N 条任务，得到"黄金轨迹"（每步的输出+动作）
② 端侧 agent 在每个 StepState 上"回放"：端侧做动作，打标签 = (端侧动作 == 目标动作 ? 1 : 0)
③ 用该标签监督分类，训练 VAS/CE 初始权重（交叉熵）
验收：IL 后策略在离线轨迹上动作一致率 > 阈值（自定，建议 >80%）
```

### 4.2 cost-aware RL（Hera 式）

```
① 以 IL 权重初始化策略，采样轨迹
② 回报 R = 任务成功 − λ·(高成本调用比例归一化)     # cost-aware，λ 调成本权重
③ 分组相同状态（跨轨迹），按"更高回报 + 更少未来高成本调用"打标签
④ PPO/策略梯度更新 VAS/CE + Critic
验收：高成本调用比例显著↓、任务成功率保持（≥ 纯端侧基线）
```

**主奖励**：Hera 式延迟奖励（上面 §4.2 ② 的 `成功 − 成本`）。
**可选 shaping（若稀疏奖励难训时再加）**：RLCascadeRouter 的增量势函数
```
U(s) = α·质量̂(s) + (1−α)·成本节省̂(s)；R_t = U(s_{t+1}) − U(s_t)；Σ R_t = 终态效用
质量̂ = (P−P_min)/(P_max−P_min)；成本节省̂ = 1 − C/C_max
```

## 5. 验收标准（M1 gate）

| 项 | 标准 |
|---|---|
| 闭环 | query → agent 多步 → 每步路由 → 任务完成，端到端可用 |
| 成功率 | 多步任务成功率 ≥ 纯端侧基线（全程本机） |
| 成本 | 高成本调用比例显著 < 纯远程基线（全程远程） |
| 校准 | P(fail) Brier score 达标 |

> **评估方法（待定，M1 实现后给方案）**：agent 多步路由的评估口径——如何像 LLMRouterBench（PGR/APR/Pareto）那样评"多步轨迹的成功率 vs 成本"（Hera 的 92.5%@46.3% 只是其中一种）→ **M1 实现后给出可选方案**。
