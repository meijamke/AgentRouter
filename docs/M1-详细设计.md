# M1 详细设计 v2 · agent 多步路由（离线答案表 + 查表训练）

> 对应《四设备模型路由·架构方案 v21》的 M1 里程碑。
> **范围**：agent 多步路由，单层 MDP，3 档设备（weak/medium/strong）。
> **v2 核心变化（守弱）**：
> 1. **主训练源 = 自建 benchmark（调硬难度分层）**，AppWorld/ALFWorld/WebShop 降级为**跨域评估**（不做训练）。原因：AppWorld 单次代码生成真执行三档全 fail（无弱强分化）；自建 benchmark GT 可验证、难度可控、无 env 生命周期 bug。
> 2. **训练 = 离线答案表 + 查表**（先一次性跑"设备×任务→对错/成本"表，之后 IL/RL 全查表，几十万局不碰真实 API）。
> 3. **IL 标签 = 最便宜够用设备（真 GT，来自答案表）**，不再是"代码不含禁用模块"的静态代理；IL 只当"不崩"初始化。
> 4. **RL 真执行查表采样 = 核心**（带 exploration，学"何时从 weak 升级到 strong"）。
> 5. **验收 = 同样成功率下成本节省**（非成功率涨分），多种子 + 误差棒，消融比 Pareto。

---

## 0. 一句话

一个 query 拆多步；每步 VAS/CE 在 {Stop} ∪ 设备里选一个；奖励 = 最终成功 − 累计成本；**训练前先建"设备×任务答案表"，训练时查表**，核心是"用最便宜的够用设备、学何时升级"。

---

## 1. 自建 benchmark（调硬难度分层）

**目标**：让 weak（Qwen3.8-Flash）/ medium / strong（DeepSeek-V4-Pro）**真实分化**。

| 档 | 题型 | 预期 | GT 可验证性 |
|---|---|---|---|
| easy | 个位数/简单算术 | 三档都过 | ✅ 数值比对 |
| medium | 多步计算 / 大数乘法 | weak 大概率错 | ✅ 数值比对 |
| hard | 复杂多步推理 / 代码生成 | 仅 strong 稳过 | ✅ 数值 / 执行比对 |

**关键（调硬）**：medium/hard 必须**真的让 weak 做错**——用大数多步计算、代码边界用例（此前"判断质数"太软，weak 全会）。建表前先做一轮"弱强分化验证"（3 题 × 3 设备，确认 weak 确实错、strong 确实对），不分化就继续调硬。

---

## 2. 离线答案表（训练前一次性建）

```
对每个 task × 每个设备：调真实 API → 拿到答案 + 成本 → 判对错（对照 GT）
→ 存成表：answer_table[task][device] = (correct: bool, cost: float)
```

- 规模：N 任务（建议 90+）× 3 设备 = 270 次 API 调用，一次性付清（~30-60 分钟）；
- 之后 IL/RL 训练**全部查表**：RL 跑几十万局，不碰真实 API，无超时、无 env bug；
- 建表即"最便宜够用设备"的 GT 来源：`label(task) = 最便宜且 correct=True 的设备`。

---

## 3. 策略网络（VAS + CE，不变）

同 v19/v20：CE self-attention 给设备打分 + VAS StopGate 消费 P(fail)；`softmax(mask([logit_stop] ∪ [logit_cont+score_i]))`。λ 条件化进状态（换 λ 免重训）。

---

## 4. 训练管线

### 4.1 IL 冷启动（只当"不崩"初始化）

- 标签 = **最便宜够用设备**（从答案表 GT 算，非静态代理）；
- 交叉熵训 VAS/CE；目的只是"先选最便宜的能答对的设备、别崩"，**不是最终路由策略**。

### 4.2 cost-aware RL（核心 · 查表采样）

```
① 以 IL 权重初始化
② 查表采样轨迹：每步策略采样设备 → 查表拿 correct/cost → 更新状态
③ 奖励 = 最终成功 − λ·累计成本（+ shaping r_t=ΔU）
④ REINFORCE/PPO + exploration（采样不贪心），学"weak 够用时别升级、weak 错时升级 strong"
```

**查表使 RL 能大规模探索**：几十万局采样，把"weak 在哪些任务错、错后升级值不值"学出来。

---

## 5. 验收标准（M1 gate · 守弱）

| 项 | 标准 |
|---|---|
| **成本节省**（主） | 同样成功率下，成本显著 < 纯 strong 基线（路由天花板=strong，收益在省钱） |
| 成功率 | ≥ 纯 weak 基线；接近 oracle（最便宜够用） |
| 统计严谨 | **多种子**（不只 seed 42）+ 报标准差/置信区间 |
| 消融 | 比 **Pareto 前沿**（多 λ），不拆两列只盯成功率 |
| 跨域 | AppWorld/ALFWorld/WebShop 上测"训好策略迁移多少"（少样本 RouteFM 路线，零样本不预设） |

---

## 6. 开发顺序

```
0 调硬 benchmark → 1 弱强分化验证（3×3 试跑）→ 2 建答案表（270 次）→ 3 IL（初始化）
→ 4 RL 查表采样（核心）→ 5 验收（成本节省 + 多种子 + Pareto）
```

> 依据：为什么单层 MDP/VAS/CE/两阶段训练 → 见架构方案 v21 §2-§4；为什么"离线答案表+查表" → RLCascadeRouter §4.3 实现细节；为什么调硬自建 benchmark → AppWorld 单次真执行全 fail，无弱强分化。
