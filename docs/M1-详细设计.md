# M1 详细设计 v5 · 统一执行决策路由（第一性原理版）

> 对应《四设备模型路由·架构方案 v23》的 M1 里程碑。
> **范围**：agent 多步路由，单层 MDP，3 档设备 × 3 执行类型 × 1 工具。
> **v5 核心（第一性原理版）**：
> 1. **骨架自推，不借论文**：单层 MDP + 统一执行决策动作空间；
> 2. **动作统一**：`{Stop} ∪ { 设备 × 执行类型 × 工具 }`，不拆"模式门 + CE"两个头；
> 3. **一个网络输出联合分布**（M1 用扁平化 softmax，10 个动作）；
> 4. **删 P(fail)**、**β 只作天花板**、**离线答案表 + 查表训练**。

---

## 0. 一句话

一个 query 拆多步；每步策略在 `{停} ∪ {设备 × 执行类型 × 工具}` 里做**一个执行决策**；奖励 = 成功 − 成本；训练前建"设备×任务答案表"、训练时查表；核心 = 学"用哪台设备 + 收尾/续步/调工具 + 何时升级"。

---

## 1. 统一执行决策（MDP 三要素，自推）

```
State  = (任务进度, 上一步输出, 累计成本 C_t, 设备状态 D_t, 步数 t, λ)
Action = { Stop } ∪ { (设备 d_i, 执行类型 e, 工具 t_j?) }
         d_i ∈ {weak, medium, strong}
         e ∈ { finalize(收尾·出答案), continue(续步·出中间结果), tool(调工具) }
         t_j ∈ { calculator }（M1 预定义 1 个可验证工具）
Reward = 成功 − 成本；γ=1；T_max=3（=设备数）
```

**动作数 = 1(stop) + 3×finalize + 3×continue + 3×tool = 10**，扁平化即可。

**"级联重试"溶解**：某步答错 → 下一步策略学出"换更强设备 + continue 重做"，是统一动作空间里的走法，不是写死规则。

---

## 2. 自建 benchmark（执行类型 × 难度 二维）

**两个轴**：①执行类型轴（让策略学收尾/续步/调工具）；②难度轴（让 weak/medium/strong 分化）。

| 执行类型 | 题型 | GT 可验证 |
|---|---|---|
| **finalize** | 单步 QA/算术（"37+25=?"）→ 一步出答案 | ✅ 数值 |
| **continue** | 多步依赖链（"先算 X，再据 X 算 Y"）→ 每步中间结果 | ✅ 数值 |
| **tool** | 调工具（"用计算器算 9876×5432"）→ 工具=可验证函数 | ✅ 执行比对 |

每类型内分 easy/medium/hard：easy 三档都过、medium weak 大概率错、hard 仅 strong 稳过。

**关键（调硬 + 分化验证）**：medium/hard 必须真让 weak 错（此前"判断质数"太软、AppWorld 单次太硬）。建表前"3 类型 × 3 难度 × 3 设备"试跑，不分化就继续调硬。

---

## 3. 离线答案表（训练前一次性建）

```
每个 task × 每个设备：真实 API → 答案 + 成本 → 判对错
→ answer_table[task][device] = (correct, cost)
→ 之后 IL/RL 全查表（解决真执行慢 + API 超时）
```

建表即"最便宜够用设备" GT 来源：`label(task) = 最便宜且 correct=True 的设备`。

---

## 4. 策略网络（一个网络，扁平化 softmax）

**不拆 VAS/CE**，一个网络输入 State、输出 10 个动作的联合分布：

```
State → Encoder → h_s
h_s → 每个动作一个 logit（Stop / 设备×执行类型×工具 各一个）→ mask → softmax
```

- 10 个动作的 logit 由一个网络直接出（M1 最简）；
- 动作空间动态 mask：offline 设备 / 不可用工具屏蔽；
- **无 P(fail)**（quality-estimator-free）；λ 条件化进 State（换 λ 免重训）。

---

## 5. 训练管线

### 5.1 IL 冷启动（只当"不崩"初始化 + Handoff target）

- 标签 = 最便宜够用设备（答案表 GT）；
- 标签用"剩余工作所需能力档 + 前方困难步"（Handoff 2610.15993），不用噪声逐步对错；
- 交叉熵训网络；目的只是"先选最便宜的够用设备、别崩"。

### 5.2 cost-aware RL（核心 + RIVET）

```
① 以 IL 权重初始化
② 查表采样：每步采样 (设备,执行类型,工具) → 查表拿 correct/cost + response → 更新状态
③ 奖励 = 成功 − λ·成本（+ shaping r_t=ΔU，γ=1）
④ RIVET：training-only response-informed value estimator，部署仍 pre-call
⑤ REINFORCE/PPO + exploration，学"收尾/续步/调工具 × 设备 × 何时升级"
```

**查表使 RL 能大规模探索**：几十万局采样，把"weak 在哪些任务错、错后升级值不值、哪种执行类型最省"全学出来。

---

## 6. 验收标准（M1 gate · 守弱）

| 项 | 标准 |
|---|---|
| **成本节省**（主） | 同样成功率下，成本显著 < 纯 strong 基线 |
| 成功率 | ≥ 纯 weak 基线；接近 oracle（最便宜够用） |
| **β 天花板** | 1−β 作"多模型组合收益上限"（只评估，不学） |
| 统计严谨 | 多种子 + 标准差/置信区间 |
| 消融 | 比 Pareto 前沿（多 λ） |
| **评测基准** | TwinRouterBench 开源仓为主；RouterWorld 补充 |
| 跨域 | AppWorld/ALFWorld/WebShop 测迁移（RouteFM 少样本，零样本不预设） |

---

## 7. 开发顺序

```
0 二维 benchmark（执行类型×难度）→ 1 弱强分化验证（3×3×3）→ 2 建答案表（3N 次）
→ 3 IL（Handoff target）→ 4 RL（RIVET + exploration）→ 5 TwinRouterBench 评估（β 天花板）
```

> 骨架（单层 MDP + 统一执行决策 + 一个网络出联合分布）是自推的；借的只有工程配方（离线答案表/IL/shaping/RIVET/Handoff）和评测（TwinRouterBench/β），换掉不影响骨架。
