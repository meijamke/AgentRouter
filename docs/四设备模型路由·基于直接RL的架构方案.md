# 四设备模型路由 · 架构设计与整体方案（agent 多步路由 v23 · 第一性原理版）

> **定位**：四设备（手表/手机/平板/PC）+ 云，做 **agent 多步路由**——一个 query 拆多步，每步做一次"**执行决策**"。
> **核心**：**单层 MDP**，直接 RL 优化「任务最终成功 − 累计调用成本」；quality-estimator-free。
> **v23 修订（第一性原理重写）**：骨架**不再"借论文"**（不再说"用 Hera/RLCascadeRouter 当骨架"），而是**从问题本身推导**——多步执行决策的必然数学形式就是单层 MDP；动作空间统一为「**执行决策 = 设备 × 执行类型 × 工具**」，不拆"模式门 + CE"两个头。论文只借"工程配方 / 评测"，不借"骨架"。

---

## 0. 第一性原理推导（骨架为什么长这样，不是谁说的）

**问题本质**：agent 任务 = 一串执行步；每步要回答一个问题——"**这一步怎么执行**"；优化目标 = "任务成功 − 累计成本"。

从这个本质直接推出四件事（无需引用任何论文）：

1. **必须建模成 MDP**：每步做决策、终点给奖励，这就是马尔可夫决策过程——**不是 Hera/RLCascadeRouter 的发明，是问题的必然数学形式**。
2. **State = 决策所需信息**：进度（到哪了）+ 成本（花了多少）+ 上一步输出（刚才干了啥）+ 设备状态（现在谁能用）+ λ（偏好旋钮）。缺哪个，决策就做不准。
3. **Action = 执行决策**：`{停} ∪ { 用哪台设备 × 执行类型 × 要不要工具 }`。**设备、执行类型、工具不是三个独立维度，而是"这一步怎么执行"这一个决策的三个属性**——所以统一成一个动作空间，不拆两个头。
4. **Reward = 成功 − 成本**：直接从目标来。

> 结论：**"骨架"是我们从问题推出来的，不是从论文抄的。** 论文里的 Hera/RLCascadeRouter/GraphPlanner 是同一推导的"同路人"，各自只补了某个细节；我们不做"挑一个当骨架"，而是自己推导。

---

## 1. 单层 MDP（统一执行决策）

```
State:  s_t = ( 任务进度, 已用成本 C_t, 上一步输出, 设备状态 D_t, 步数 t, λ偏好 )
Action: a_t ∈ { Stop } ∪ { 执行决策 = ( 设备 d_i, 执行类型 e, 工具 t_j? ) }
        执行类型 e ∈ { finalize(产出最终答案·结束), continue(产出中间结果·继续), tool(调用工具) }
        d_i ∈ 在线可执行设备（动态集合）；t_j ∈ 预定义工具集（M1=计算器）
Reward: R = 任务最终成功 − Σ 各设备调用成本
折扣/深度: γ = 1；T_max = 可执行设备数（M1 = 3 档 → T_max=3）
```

- **"级联重试"溶解进动作空间**：某一步答错了，下一步策略自然学出"换更强设备 + continue 重做"——不是一个写死的规则，而是统一动作空间里策略学出来的走法（Handoff Curves 实证：handoff 是策略决策，不是写死机制）。
- **动作数（M1）**：Stop(1) + 设备3 × {finalize(3), continue(3), tool(3×1工具=3)} = **10 个动作**，扁平化即可。

**成本函数**：`κ(d_i) = c_tier(cap_embed_i) + λ_lat·延迟 + λ_energy·能耗 + λ_kv·KV`（本机 kv=0；云最贵）。

**λ 条件化进 State**（吸收 RouteFM）：换 λ 免重训，不是"一个 λ 一个策略"。

---

## 2. 策略网络（一个网络，输出联合分布，实现自由）

**本质**：一个网络，输入 State，输出 `P(动作 | State)` 的联合分布。

**实现是设计自由，不强制 VAS/CE 二分**：

```
最简单（M1 用）：扁平化 softmax —— 对所有 10 个动作直接出概率
可选（M2 再上）：因子分解 P(设备,执行类型) = P(设备|state)·P(执行类型|state,设备)，
                或 P(执行类型)·P(设备|执行类型) —— 选哪种是设计选择，不是照搬
```

- **没有"模式门"和"CE"两个分开的头**——因为"选设备"和"选执行类型"本就是同一个决策，拆开反而是引入论文的偏见；
- 唯一的约束：输出必须是合法的联合概率分布（softmax / 分层 softmax），动作空间动态 mask（offline 设备 / 不可用工具屏蔽）。

**无 P(fail)**：quality-estimator-free，不建质量估计器、不设校准阈值；升级信号推迟 M2 且过"五种自欺"清单。

## 3. 训练（直接 RL + 工程配方）

### 3.1 离线答案表（训练前一次性建）

```
每个 task × 每个设备：调真实 API → 答案 + 成本 → 判对错
→ answer_table[task][device] = (correct, cost)
→ 之后训练全查表，几十万局不碰真实 API（解决真执行慢 + API 超时）
```

### 3.2 IL 冷启动（只当"不崩"初始化 + Handoff target）

- 标签 = 最便宜够用设备（答案表 GT）；
- 标签用"剩余工作所需能力档 + 前方困难步"（Handoff 2610.15993，monotone fit），不用噪声逐步对错；
- 交叉熵训网络；目的只是"先选最便宜的够用设备、别崩"。

### 3.3 cost-aware RL（核心 + RIVET）

```
① 以 IL 权重初始化
② 查表采样：每步采样 (设备,执行类型,工具) → 查表拿 correct/cost + response → 更新状态
③ 奖励 = 成功 − λ·成本（+ 增量 shaping r_t = U(s_{t+1})−U(s_t)，γ=1 → 轨迹回报=终态效用）
④ RIVET（2610.23239）：training-only 的 response-informed value estimator，部署仍 pre-call
⑤ REINFORCE/PPO + exploration，学"用哪台设备 × 收尾/续步/调工具 × 何时升级"
```

**β 只作评估天花板（1−β）**：β 是反事实宏观量（运行时不可得），不进 RL 输入、不做 ROI gate、不做模式剪枝。

## 4. 数据模型

| 结构 | 字段 |
|---|---|
| `DeviceState` | device_id, cap_embed, battery_pct, temp_c, mem_free_gb, network_bw_mbps, can_execute, online |
| `StepState` | 任务进度, 上一步输出, C_t, D_t, t, **λ** |
| `StepAction` | action(Stop / 设备×执行类型×工具) |
| `StepObservation` | latency_ms, energy_j, kv_bytes, kv_ms, quality, success |
| `TrainingRecord` | 轨迹 + 终态效用 + 该步 response |
| `StrategyPackage` | version, 网络权重 |

## 5. 模块清单

| 层 | 模块 | 输入 → 输出 |
|---|---|---|
| L1 | 设备发现·心跳 / 状态采集 | — → List\<DeviceState\> |
| L2 | 状态编码 | 进度+输出+设备状态+λ → StepState |
| L2 | 策略网络 | StepState → 动作联合分布 → StepAction |
| L3 | 执行器 | 动作 → 输出+观测（本机0迁移 / 跨设备 KV） |
| L4 | 离线答案表 + IL + RL | 轨迹 → 网络权重 |

## 6. 演进路线

### 6.1 里程碑

| 里程碑 | 交付 | 验收 |
|---|---|---|
| **M1** | 统一执行决策路由：单层 MDP + 一个网络 + IL/RL（3 设备 × 3 执行类型 × 1 工具） | 同样成功率下成本节省；多种子+误差棒；Pareto；β 天花板 |
| **M2** | 在线更新（MixLLM bandit + 候选集动态）+ 升级信号（过五自欺清单） | regret↓、无退化 |
| **M3** | 四设备全池 + KV 迁移 | 延迟↓、KV 成本↓ |
| **M4** | 路由内化 + 自我改进 LLM（四门槛） | 有条件才动 |

### 6.2 评估口径

- **成功率@成本 → Pareto**；基线含 纯弱/纯强/oracle/随机/RSI-Router；
- **天花板**：路由天花板=池内最强设备；β 只作"多模型组合上限 1−β"；
- **统计严谨**：多种子 + 标准差；**消融比 Pareto**；
- **评测基准**：TwinRouterBench 开源仓（per-step + live SWE-bench）为主，RouterWorld 补充；
- **跨域**：AppWorld 训 → WebShop/ALFWorld 测；最多 RouteFM 少样本迁移，零样本别预设。

---

## 7. 设计红线（守弱 5 条）

1. 不预设「自我改进会稳定增益」；2. 技能/训 LLM 不是免费午餐；3. 在线更新会退化（回滚+锚校验）；4. 每轮更新必做新vs旧对照（rsi_eval 式）；5. 零样本跨域是开放问题。

## 8. 论文"借用清单"（明确：借的是配方/评测，不是骨架）

| 借的 | 性质 | 用途 |
|---|---|---|
| 离线答案表（RLCascadeRouter 实现细节） | 工程配方 | 训练加速 |
| IL 冷启动 + shaping（Hera） | 工程配方 | 训练稳定 |
| RIVET response-informed / Handoff supervision target | 训练技巧 | 解中间步奖励 / 标签质量 |
| REINFORCE/PPO | 通用 RL 算法 | 训练（不是任何论文的"公式"） |
| λ 条件化（RouteFM）/ 删 P(fail)（守弱） | 设计选择 | 换 λ 免重训 / quality-estimator-free |
| TwinRouterBench / RouterWorld / β | 评测 | 打分 / 天花板 |
| MixLLM / RSI / NeoHorse / RouteFM | 参考 | M2/M4 方向 |

> **骨架（单层 MDP + 统一执行决策 + 一个网络出联合分布）是我们从问题推出来的，不是借的。** 上表所有"借的"都是可替换的配方或评测，换掉不影响骨架成立。
