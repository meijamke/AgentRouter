# AgentRouter 改进路线 · 守弱版

> **定位**：基于对「RSI 自我改进家族」（NeoHorse 2609.08183 / RSI-Router 2609.34712 / SPIN / ReST-MCTS / Tao / Dream-RSI / CERA-MoA 等）的守弱对比，给出的**下一步开发路线图**。
> **守弱** = 假设「自我改进会稳定增益」这件事**本身没被证明**，优先做低风险、可证伪、能验证的，把高风险不确定项拆成「证伪条件」，不满足就砍、就回退。

---

## 0. 三维坐标定位（先说清我们在哪）

| 方案 | X 更新对象/深度 | Y 反馈信号硬度 | Z 路由器位置 |
|---|---|---|---|
| **AgentRouter（我们）** | 0.45 训路由器 | 0.60 偏硬 | 0.10 外部 |
| RSI-Router 2609.34712 | 0.05 改文本策略 | 0.62 偏硬 | 0.25 外部 |
| NeoHorse 2609.08183 | 0.95 训 agent LLM | 0.50 中 | 0.90 内部 |
| CERA-MoA | 0.55 两者同训 | 0.55 中 | 0.85 内部 |

**演进主轴**（四点勉强成一条对角线）：
```
外部·改文本（RSI-Router）→ 外部·训路由器（AgentRouter）→ 内部·训 LLM（NeoHorse/CERA）
        ↑ 我们在这里
```

AgentRouter 现在改的是「路由器」（中段），势能区在「改模型本身」（训 LLM 顶端）。**中间不是一层纸，是三道坎：训谁、反馈可不可靠、有没有训练预算。**

---

## 1. 守弱底线（一句话）

> **不动核心**（单层 MDP + VAS/CE + 训路由器，这是站稳的地基）；**只补三件事**（子任务特征、技能增强、路由器级反馈闭环）；**明确不跳级训 LLM**（M4 门槛不满足就空转）。

---

## 2. 三层改进路线（守弱优先级 + 证伪条件）

> **修订注（2026-11）**：本节的「三层」是**时间顺序**（现在/中期/远期），**不是** RSI 家族的「三档」（按**更新对象**分：训权重 / RSI 标签集 / 改笔记）。此前把两者硬套，导致三处错位，已在本节内修正：
> - RSI-Router 的「技能/子任务」= **第三档（改笔记·不动权重）**，天花板被底座锁死 → 降级进 1.2；
> - SPIN / ReST-MCTS = **第一档（训权重）**的成熟做法，应**前移到 M1-M2 做数据治理** → 新增 1.4；
> - 第二档的 rsi_eval / Formal-Verification-RSI 的眼光（防退化评测 + 验证器可靠性）→ 补进红线。

### 层 1（M1→M2 · 现在做 · 强证据 · 低风险）

| # | 改进 | 做法 | 证伪条件（不满足就砍） |
|---|---|---|---|
| 1.1 | **子任务挖掘 → 替换手工 progress** | 从执行轨迹自动挖「Locate/Implement/Verify」→ 作 VAS/CE 状态特征 | AB 不赢手工 progress → 不用 |
| 1.2 | **技能 → 设备执行增强（第三档·改笔记，有天花板）** | 给「子任务 × **能力档**」生成技能 prompt（绑能力档**不绑模型名**，v19 吸收原则）；**定性 = 有限增益的 prompt 增强，非能力进化** | 技能 token 代价 > 质量/成本收益 → 砍（侵蚀 1ms 延迟）；**天花板=设备底座锁死，无法让设备变强** |
| 1.3 | **路由器级「评估→选择→更新」闭环** | NeoHorse 式闭环，但**只更新路由器权重**；M2 bandit 在线精调 + 触发式更新 | 分布漂移下 regret 不降 → 路由器这层还没站稳 |
| 1.4 | **训练数据治理（第一档·前移）** | ReST-MCTS 式过程奖励 + 树搜索，**只挑可验证正确的轨迹**重训；SPIN 式设备间自对弈判别做中间信号 | 治理后的 IL/RL 不赢「静态/真执行标签」→ 数据治理无增益，回退简单标签 |

**核心思想**：把「路由器这一层」做到能自我改进、反馈可验证——这是 M4 的一切前提。

### 层 2（M2→M3 · 中期咽喉 · 中证据 · 必须自己 AB）

| 改进 | 做法 | 证伪条件 |
|---|---|---|
| 2.1 **无 GT 场景的验证器（仅 R2V）** | R2V 过程验证器（ReST/SPIN 已前移到 1.4）；**硬门槛 = 验证器本身要可靠**（Formal-Verification-RSI 的关注点：验证器不可靠 → reward hacking） | 替代信号训出的路由器跨域不赢「纯 GT 训练」→ 反馈替代不可用，M4 需另寻信号 |
| 2.2 **触发式更新** | 分布漂移 / 设备池变化作触发器（非固定定时） | 在线更新退化 → 保留回滚 + 外部锚周期校验 |

> 「无 GT 反馈」是从「训路由器」通往「训 LLM」的**唯一咽喉**——但**反馈信号的"生成"（ReST/SPIN，第一档）应前移到 M1-M2 做好数据治理；这里只剩"验证器的可靠性"这条硬门槛**。当前 M1 全靠 benchmark GT，还没到非补不可，但它是 M4 的前置。

### 层 3（M4+ · 远期 · 弱证据 · 有条件才动）

**路由内化 + 训 agent LLM（NeoHorse / CERA 终局）**。

四个门槛（**全满足才启动**）：
1. 可靠验证器（开放域没有 GT 就没法训 LLM）；
2. 训练预算；
3. 能防 reward hacking；
4. 跨域泛化证据。

**不满足 → 回退「只训路由器」**，不空转、不负优化。

---

## 3. 四条守弱红线（贯穿全程）

1. **不预设「自我改进会稳定增益」** —— 这件事本身没被证明（Formal-Verification-RSI、rsi_eval 存在的理由就是防它）。
2. **技能 / 训 LLM 不是免费午餐** —— 先量化代价（技能是追加 token、会侵蚀延迟），不达标就砍。
3. **在线更新会退化** —— 保留版本化回滚 + 外部锚周期校验（v19 设计红线第 3 条，继续当真）。
4. **每轮更新必须做「新 vs 旧权重」对照评测**（rsi_eval 式）—— held-out 集上证明不退化、才准上线，只看绝对成功率不算数。

## 4. 落地路线图（对应到里程碑 / 代码 / 文档）

| 阶段 | 对应里程碑 | 要做的事 | 当前状态 |
|---|---|---|---|
| **现在** | M1 | 三个 benchmark 跑通真实训练（AppWorld 真执行 + 静态 IL；ALFWorld/WebShop 接 adapter） | AppWorld 训练后台跑；ALFWorld 待 make、WebShop 待数据 |
| **下一步** | M1→M2 | 层 1.1 子任务特征（AB 对手工 progress）、层 1.2 技能（量化 token 代价）、层 1.3 M2 bandit 在线精调 | 未开始 |

**每一步都带证伪条件**：证伪了就往回退，不往上跳。

---

## 5. 一句话总结

> 改进的稳妥顺序不是「复刻 RSI 家族的终局形态」，而是反过来：**先把「路由器这一层」做到能自我改进、反馈可验证，M4 的 LLM 级自我改进才成立**。
> AgentRouter 最该学 RSI 家族的，是「**反馈闭环 + 能力档抽象**」；最容易学坏的，是把「技能」「训 LLM」当成免费午餐。
