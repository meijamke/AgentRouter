# RSI-Router 精读与对比

> 来源：arXiv 2609.34712《RSI-Router: Evolving Subtask-Level LLM Routing and Skills for Cost-Efficient Agents》，上海人工智能实验室，已读全文 PDF。
> 用途：与本方案（AgentRouter，VAS/CE 训练网络路由）做逐项对比，指导 M4 演进。

---

## 1. RSI-Router 是什么（一句话）

用**大模型当"进化引擎"，递归自改进「子任务级路由策略 + 模型专属执行技能」**——不训练任何权重，纯靠大模型生成文本策略、评估、择优。

**结果**：DeepSeek-V4.1-Flash(大) + Qwen3.5-9B(小)，5 个 benchmark 平均省 51.7% 成本、性能不降反升；ALFWorld 成功率 90.62%→98.44% @ 成本降 75.3%，Pareto 前沿碾压 9 个基线。

---

## 2. 四阶段进化循环（精读）

由 **proposal agent（Codex）** 驱动，跑 G=6 轮，每轮 N=4 个候选策略，维护 Pareto 种群 P + 被支配归档 F。

| 阶段 | 通俗类比 | 严格做法 |
|---|---|---|
| **① Subtask Mining**（子任务挖掘） | 切块 | 分析训练轨迹，按"执行目标"分段→跨轨迹聚类成子任务集 Z（如 Locate/Implement/Verify），写定义+识别规则；第 2 轮起保留/拆分/合并；回放校验可识别性 |
| **② Routing Strategy Evolution**（路由策略进化） | 排班 | 并行生成 N=4 个候选策略（每策略给每子任务指定 L 或 S），从共享技能库选择性继承技能，训练+验证集评估 |
| **③ Model-Specific Skill Evolution**（技能进化） | 写小抄 | 对比候选路由器 vs 纯大模型 r_L 的同任务轨迹，诊断"模型专属失败模式+冗余动作"，refine/生成"子任务×模型"专属技能 prompt，re-evaluate |
| **④ Pareto-Optimal Router Selection** | 淘汰 | 按验证性能+成本，非支配→P_{t+1}，被支配→F_{t+1}（当反例）；P、F 都留供下轮继承 |

**关键**：每一环节都是"大模型生成文本→评估→择优"，是**离散搜索**，不是梯度优化。

---

## 3. 部署方式（三模型分工）

| 角色 | 模型 | 部署 | 成本 |
|---|---|---|---|
| 大模型 L（执行主力） | DeepSeek-V4.1-Flash | 云端 API | 官方价 |
| 小模型 S（执行 + 当路由器） | Qwen3.5-9B | 自托管 H200 GPU | 1:30 价格比（GPU 时折算） |
| proposal agent（进化引擎，仅离线） | Codex | 第三方 API | 训练侧，不计测试成本 |

推理时只有 L + S 两个模型，**小模型 S 兼职当路由器**（读"子任务定义+识别规则+前3步历史+技能"→预测子任务→查表选模型→追加技能）。

## 3.5 协作与数据流（参考 Agent 的 Model-Harness 闭环结构）

**AgentRouter**——Router 是「读独立特征向量的旁路决策器」，**只**回答"上下文喂给哪台设备"，上下文不动、不追加任何内容：

![AgentRouter harness 结构](../diagrams/agentrouter-harness.png)

**RSI-Router**——Router = 小模型 S + 查表，**既**回答"喂给 L 还是 S"（选模型），**又**往被选模型的输入里追加技能文本：

![RSI-Router harness 结构](../diagrams/rsirouter-harness.png)

**准确对比**（两者都"选模型"，RSI 额外多"追加"）：

| | 选模型（改接收者） | 追加内容（改输入） |
|---|---|---|
| AgentRouter | ✅ 独立网络读特征向量选设备 | ❌ 无 |
| RSI-Router | ✅ 小模型 S 预测子任务 → 查表选 L/S | ✅ 追加技能文本 |

关键：**两者都"选模型"**——差别是 AgentRouter 用「独立网络、读特征向量」选（多设备、不追加），RSI 用「小模型预测子任务 + 查表」选 L/S，且额外"往被选模型输入追加技能"。

## 4. 与 AgentRouter 逐项对比

| 维度 | RSI-Router | AgentRouter |
|---|---|---|
| 路由粒度 | subtask 级 | step 级 |
| 路由器形态 | 小模型 prompt（不训权重） | 训练小网络 VAS/CE |
| 路由学习 | 大模型离散搜索（生成→评估→择优） | IL + cost-aware RL（梯度） |
| 技能演化 | ✅ 有（子任务×模型 prompt） | ❌ 无 |
| 子任务挖掘 | ✅ 有 | ❌ 无（progress 手工特征） |
| 更新对象 | 路由策略（文本）+ 技能（文本） | 路由器（权重） |
| 在线更新 | ❌ 无（离线 G=6 一轮） | ✅ M2 云侧 bandit |

## 5. 六个关键判断

**① "RSI 质量更优"未实证**：它碾压的 9 个基线里没有"训练网络路由器"这类 VAS/CE 同款，开放问题。

**② 延迟差距仍在 1000 倍量级**：RSI 每步路由 = prefill 1000+ token（0.5–1.5s）+ 生成 20–50 token @200token/s（0.1–0.3s）；VAS/CE 一次前向 ~1ms。且 RSI 的路由是"每步额外多一次小模型调用"。

**③ 质量差距来自"子任务级 + 技能"，不是"prompt 路由"** → 可吸收，吸收后 AgentRouter 更优（推断，待实证）。

**④ 可审计性收窄**：决策过程两者都黑盒；RSI 的优势只在"策略文本可读"，决策过程无优势。

**⑤ 训练频率**：RSI 离线批量一次（重训频率论文未提）；AgentRouter = M1 离线 + M2 在线持续。

**⑥ 重训触发点对比**（见下表 + 架构方案 §7.1）：

| 触发事件 | RSI-Router | AgentRouter |
|---|---|---|
| 端侧小模型换掉/升级 | ⚠️ 重训（技能绑死模型，失效） | ✅ cap_embed 更新 + M2 在线精调 |
| 云侧大模型换掉 | ⚠️ 重训（参照轨迹 r_L 变了） | ✅ 同上 |
| proposal agent 换 | ✅ 不重训（只影响下一轮） | 无对应 |
| 任务分布漂移 | ⚠️ 重跑整个进化 | ✅ M2 在线 bandit 精调 |
| 设备池变化 | 未涵盖 | ✅ 动作空间动态 mask |

**核心差异**：RSI 技能**绑死具体模型**（换模型就作废）；AgentRouter 绑死**能力档 cap_embed**（模型可替换）。

## 6. 可落地吸收（指导 M4）

**① 子任务 → VAS/CE 状态特征**：把 RSI 的"子任务识别"（Locate/Implement/Verify）作为一个特征塞进 StepState，替换粗糙的手工 progress。VAS/CE 由此能"按子任务"精细路由。

**② 技能 → 设备执行增强**：执行时给选中设备追加"子任务×设备"专属技能 prompt，临时提升它的有效能力（等价 cap_embed 临时提升）；VAS/CE 决策时"知道"戴技能后设备更强，更敢派弱设备。

**③ 端侧"轻评估+轻改进"三层分工**：

```
第 1 层（现状）：云侧评估 + 云侧改进（离线），端侧只执行
第 2 层（M2，我们已设计）：端侧轻评估+轻改进（即时信号调阈值/偏好）+ 云侧重评估+重改进（训权重）
第 3 层（M4 终局）：端侧自我反思 + 自我改进技能（路由内化为 agent 能力）
```

**④ 触发式更新**（比固定定时更优）：

```
触发条件（满足任一就更新）：
  ① 累计新轨迹数 ≥ N（云侧攒够 N 条）
  ② 检测到分布漂移（成功率/成本连续下降、设备能力档变化）
  ③ 设备池变化（新设备加入/老设备下线）
频率参考：端侧阈值分钟级、云侧权重 24h/按批、完整重进化周级、增量技能日级
```

---

## 结论

RSI-Router 是"**大模型离散搜索生成文本策略+技能**"范式，AgentRouter 是"**梯度训练轻量网络**"范式。两者不是替代关系：

- RSI-Router 前瞻的是「技能演化 + 子任务挖掘」（模型能不能被增强、任务结构能不能被自动发现）；
- AgentRouter 前瞻的是「轻量可部署、高频低延迟、可在线精调」（路由决策本身要便宜可训）。

**最完整 = 我们的 VAS/CE 独占"选设备"决策 + RSI 的"子任务、技能"做输入/增强 + 触发式在线精调。**
